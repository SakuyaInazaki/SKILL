# 课件解释 Skill

## 强制执行：输入切分与子 agent 协作（任务开始时必读）

**本节为主 agent 的前置执行要求。运行环境支持子 agent 时，主 agent 必须在开始撰写逐页逐句解释前实际启动子 agent，分配适合独立处理的块；不得将协作当作可选建议，不得只写出分工计划而不实际调用。** 环境允许配置时，优先使用相同模型和思考强度。不能配置这些选项时，不声称已经统一。不支持子 agent 时，应说明具体限制，再由主 agent 按相同分块与验收规则顺序执行。

对长材料，先建立全局计划，再在章节内部按小主题和完整论证单元分块，不默认把整章交给一个子 agent。输入类型用于决定局部解释方式，不作为机械切分的首要依据。避免将同一段证明的前后部分，或同一例子的代码、性能结果和结论拆成缺少上下文的独立任务。

**默认每块包含约 3–5 张有实质内容的逻辑幻灯片，围绕一个小主题或一组紧密关联的问题展开。** 内容密集、推导较长或代码分析复杂时，可缩小到约 1–3 张；内容较轻且高度连贯时，可合并到约 5–8 张。这里按筛选后的逻辑幻灯片计数，不按 PDF 物理页、展开帧或输出讲义页计数；教材则按较短小节、完整概念或完整例题采用相近的任务规模。

这些范围是分块参考，不是机械页数配额。不要细到每句话、每条公式或每个普通页面都单独建立任务；一个完整证明或例子跨越较多页面时，优先保留完整上下文，确需分块则须明确依赖与衔接。超过约 8 张有实质内容的逻辑幻灯片时，应重新检查能否在小主题边界拆分；决定保留较大块时，在内部记录中说明理由。还应计入预计推导、延拓和核查的工作量，不能只按原页数量平均分配。

主 agent 负责全局计划、范围划分、术语和符号约定、首次讲解位置、跨块衔接、验收、返修与最终合并，不能只在最后拼接各子任务的输出。

每个子任务必须接收并读取完整的本 skill，并另行收到以下任务上下文：

- 本次讲解范围、来源文件与页码映射，以及该子任务负责的明确边界。
- 学生基础、已确认的用户要求、共享术语与符号约定。
- 必要的前后文、前置知识、已讲解概念及准确回指，跨块问题的处理约定。
- 预期输出位置、交付形式、统一的原句块与视觉层级模板，以及适用于本块的检查要求。

不能以“下面的部分”等位置指代替代完整规则，也不能只传递逐句讲解要求而漏掉来源、输出和验收规范。不得擅自删改核心讲解规范；允许且应当增加当前子任务必需的范围、上下文和已确认约定。若无法可靠传递这些信息，应缩小任务或改为顺序执行。

每个子任务返回讲解正文、已覆盖内容、引用来源、未解决问题，以及需要跨块衔接的位置。主 agent 核查重复内容与缺口，统一术语、符号、编号和引用，并检查跨页证明、例子及结论是否连续。

## 强制执行：讲义取舍与阅读呈现（开始写作前必读）

**最终讲义不生成目录、导读、阅读指南或章节预告，不展示、不解释纯目录、纯导读、纯过渡或仅含主题标题的非知识性页面。逐句解释必须采用“浅色底原句块＋连贯自然段”的形式；英文原句以“中文译句（原文：英文原句）”呈现。标题、解释内的小标题和关键统领语句应有统一、可辨认的视觉层级。**

“逐页逐句”要求适用于筛选后保留的实质性内容，不能被用来为纯标题页或过渡页填充解释。具体判定遵循“非知识性页面的筛选与省略”，排版遵循“逐句原句与连贯解释的排版”和“标题、统领句与视觉层级”。本 skill 中的执行清单不是讲义正文的分点模板。

## 准备工作

### 任务范围与学生基础

本 skill 面向希望深入理解大学课程的学生，尤其适用于希望追问知识从哪里来、为什么成立、如何使用，以及适用边界在哪里的学习需求。目标是形成可供深入学习的讲义，而非简短摘要。

开始时先确定本次讲解范围，以及各文件的角色：主要讲解对象、参考资料或补充材料。完整覆盖要求仅适用于本次确定的讲解范围。用户指定局部页码、章节或问题时，不自动扩展为全部文件；为理解当前主题所需的先修知识，以及有助于贯通知识的范围外延伸可以主动补充，但应说明与当前主题的关系、用途和来源，不将这种延伸变成对范围外材料的自动逐页讲解。

默认以课件为主要讲解对象，配套教材用于核查和补充，不因教材同时上传就自动逐句讲解整本教材。仅提供教材时，用户已经明确要求讲解的，按其指定范围采用教材讲解方式；范围仍不明确且会显著影响工作量时，再进行必要确认。

优先使用用户已经说明的课程背景、先修知识、学习目的和困惑点。信息不足时，结合课程与材料声明本次采用的基础假设，不把假设当成已经确认的用户特征。只有当缺失信息会显著改变讲解范围、深度或正确性时，才向用户确认，不重复询问材料中已经给出的信息。

### 输入格式与预处理

用户可能提供课件 PDF、课件 PPT、由 PPT 导出的 PDF、教材，以及这些资料的英文版本。

保留原始文件，所有转换、裁切与合并均在副本上进行，不覆盖原文件。

- 对一页一张幻灯片的 PDF，直接建立页码索引并检查内容是否完整可读。
- 对 PPT，在工具支持时转换为 PDF，并核对转换结果。不能完成转换时，说明限制和受影响范围，不假装已经取得完整的 PDF 版本。
- 对一页多张幻灯片的 PDF，例如一页六张，按实际版式拆分或裁切，核对阅读顺序，保留每张幻灯片在原物理页中的位置。
- 对英文材料，保留英文原版并提供对应中文翻译；具体排版统一遵循“原页对应与版面要求”。

需要理解图示、图表、公式、代码排版或状态变化时，应查看原页视觉内容，不只依赖提取后的纯文本。文字提取与视觉读取仍不能可靠辨认时，才考虑可用的 OCR 工具，并回看原图核对识别结果。无法辨认的内容应标记具体位置，不通过猜测补成原文。

### 针对不同输入的解释策略

幻灯片往往省略背景和中间步骤。你的任务是展开每个要点，解释各要点之间的关系，并补齐理解当前内容所必需的逻辑环节。补出的关系若不是材料明示的内容，必须按“来源、不确定性与疑似错误处理”说明其性质。

教材通常比幻灯片提供更多上下文，但不能预设它已经完整、没有错误或适合学生当前基础。借鉴教材时，清晰地重新陈述相关内容，解释每个关键论断背后的“为什么”，核对版本、符号约定和适用条件。不要仅换一种说法，也不要把整章无关内容搬入讲义。

对混合或含糊的内容，在有依据的范围内充分解释；无法确定时应充分说明不确定性，不能为了篇幅完整而补出确定答案。

### 原始 slide 预处理规则

判断连续页面是否属于同一张 slide 的逐步展开过程时，应同时检查页脚或角标、标题、版面主体和新增内容。同一个编号，例如 `8/25`，只能作为线索，不能单独作为合并依据。

仅当确认这些页面属于同一张 slide 的构建过程、最后一帧包含前面各帧的全部实质信息，且中间状态对理解过程没有独立价值时，才将该组展开页合并为最终状态。

若存在被覆盖的内容、关键中间步骤、错误示范或有教学意义的状态变化，应保留相关帧，或在保留原始来源的基础上明确重建这些变化。不能只留下最后一帧而丢失教学过程。

若角标相同但内容主题明显不同，不得机械删除。不能确认是否可以合并时，默认保留，并记录待确认事项。所有合并、裁切和省略展示的操作均应记录判断依据及原始页码对应关系。

### 非知识性页面的筛选与省略

分块与写作前，先区分具有实质性知识的页面和仅用于组织展示的页面。纯目录页、纯导读或议程页、章节分隔页、纯过渡页，以及只有课程名、章节名或主题标题而没有实质内容的页面，均不进入最终讲义的展示与解释范围。这是省略交付中的展示，不是删除或覆盖原始文件。

**只有一行主题标题的页面不得扩写成一页解释，也不需要改写成一段简短说明。** 不为这些页面建立独立讲解单元、原页展示、空白占位或“本页无需解释”的说明页。确有组织作用的主题名称可直接作为后续知识性单元的标题，不为此另写导读或章节预告。

不要只按字数、行数或页面名称判定。只有一行的实质性定义、定理、公式、关键论断或需要解答的问题，仍应按内容深入解释；标题或导读式页面中包含独有的实质性信息时，应保留并解释这些信息，必要时保留相关原页或可定位的局部图，不按页型整页误删。仅起组织作用的文字不单独解释。

被省略的页面只在内部页码映射和覆盖记录中登记原始位置及省略理由，不占用讲义篇幅，也不向学生逐页展示省略清单。保留其原始页码，讲解单元编号记为不生成；来源编号出现间隔不等于内容遗漏。

### 预处理核查与页码映射

预处理完成后，核对处理前后的页数关系、阅读顺序、图表、公式、代码、关键标注和需要保留的展开状态。检查转换或裁切是否造成信息遗漏、遮挡或不可读缩放。存在缺失时，先尝试补救；仍无法恢复的，记录受影响范围。

统一区分以下编号，不混用“一页”的含义：

| 编号 | 含义 |
| --- | --- |
| PDF 物理页码 | PDF 文件中的实际页面位置，默认从 1 开始。 |
| 原课件页码 | 原课件显示的页脚或角标编号；没有则记为无。 |
| 逻辑幻灯片编号 | 拆分与合并处理后，为每张逻辑幻灯片分配的稳定编号。 |
| 讲解单元编号 | 对应解释正文的稳定定位标识；单元可以跨越多张输出纸页。 |
| 输出讲义页码 | 最终排版后的纸面页码，可能随排版调整而变化。 |

为每个讲解单元保留以下映射：

```text
源文件 → PDF 物理页码 → 合版位置或展开帧范围
      → 原课件页码 → 逻辑幻灯片编号 → 讲解单元编号
```

教材作为主要讲解对象时，以其章节、原始页码和必要的段落或题号建立对应关系，不强行使用幻灯片编号。不同文件的相同页码必须通过文件标识区分。

## 执行与记录

### 进度记录与断点续作

在当前项目的约定位置维护进度记录，与用户偏好记录分开。记录形式以便于实际维护为准，不必为了记录而创建大量文件。

进度记录至少包含本次范围、页码映射、非知识性页面的省略判定、分块分配、共享术语与首次讲解位置、各块状态、未解决问题，以及编译与检查结果。各块状态区分为未开始、草稿完成、已校验、待确认；存在实质性缺口的块不能标成已完整校验。

完成一块或发现会影响后续内容的问题时，更新记录。任务续作时，先读取已有产物和记录，确认已完成内容与当前约定，不仅凭先前对话的简要概述继续。

### 用户偏好记录：`NOTES.md`

用户有时会明确表达解释风格、已掌握知识、术语偏好或希望在项目中沿用的要求。在当前项目的约定位置读取或维护 `NOTES.md`，只记录用户明确表达或已经确认的偏好与基础，不把临时推测写成长期特征。

对于风格、深度和呈现方式，本次明确要求优先于历史偏好，历史偏好优先于本 skill 的默认值；这些偏好不能覆盖准确性和来源标注要求。本 skill 的执行同时受运行环境中更高优先级的约束限制。

任务进度、临时推导和未解决问题写入进度记录，不与稳定偏好混在一起。运行环境不支持文件持久化时，应说明限制，不声称已经保存，也不将项目内记录描述为跨项目永久记忆。

## 核心理念

1. **详尽无遗，而非总结。** 必须处理本次讲解范围中的每个实质性概念、定义、定理、符号和论断，不因内容看起来显而易见就跳过。逐句覆盖与原文对应关系必须可核查。
2. **直觉服务于准确理解。** 为抽象内容提供与学生基础相匹配的直观解释、具体例子或执行推演。可以先提出问题、先给直觉或先作形式化陈述，但最终必须明确准确的定义、条件和结论，不用类比替代它们。
3. **证明要逐步讲解。** 对材料给出的证明和为本次理解确有必要补充的证明，解释每一步的依据、目的、所用条件和衔接关系。只有证明思路时应标明，不把省略关键步骤的提纲称作完整证明。
4. **简单的事情保持简单。** 解释篇幅与内容难度、学生基础及逻辑缺口相匹配。简单想法可以用两三句准确说明；困难内容则展开动机、先决知识、中间步骤与适用边界。不要堆叠类比，不要为一步能讲清的内容铺垫五步，也不要为了赶进度压缩真正困难的部分。

### 学习目标与理解检查

讲解应同时服务于当前理解、脱离原文后的提取，以及后续应用和迁移。不要仅凭读者觉得顺畅，或刚看完能够复述，就宣称已经实现长期掌握。

所创建的解释应具有系统学习的完整性，为学生建立细致、连贯、可追溯的知识结构。学生的目标不仅是完成课程与考试，更是理解知识的来龙去脉，并把不同概念、方法和学科中的联系贯通起来；不得将考试范围或“刚好能做题”当成解释深度的上限。重点检查学生能否用自己的话说明核心概念，解释关键步骤的理由，辨认适用条件，说明知识之间的联系，并处理与示例有所变化的问题。

可以在一个完整知识单元结束后附少量自检问题，将答案与问题分开呈现。自检不得替代完整讲解，也不应无必要地频繁中断说明。没有实际的学习反馈时，不声称已经测得学生的掌握程度。

## 讲解流程与指南

### 全局浏览与执行顺序

先浏览本次材料的整体结构，确定章节关系、知识依赖、跨页证明、贯穿例子，以及符号是否在后文才给出定义。全局浏览用于避免局部解释与后文脱节，不代替逐页逐句讲解。这些规划留在内部记录中，不另行输出目录、导读或阅读路线。

按以下顺序执行：

```text
确定讲解范围、材料角色与学生基础
→ 浏览整体结构并完成必要预处理，筛除纯目录、纯导读和纯过渡等非知识性页面
→ 建立页码映射、术语约定与知识依赖
→ 按章节内小主题细分任务并依照前置协作要求实际分配子 agent，按原材料顺序解释保留的实质性内容
→ 应用相关页型规则，核查来源与逻辑
→ 检查覆盖情况与跨块一致性
→ 排版、编译并检查最终文件
→ 交付已完成产物，说明遗留问题与受影响范围
```

需要提前介绍后文概念时，先补足理解当前内容所需的部分，并标明正式定义或完整解释的位置；有助于贯通当前主题的深入联系可以按“知识延拓与贯通”继续展开，不以最低理解需求为上限。调整解释顺序不能破坏原页对应关系，也不能将本次范围外的材料自动变成新的全面逐页讲解任务。

### 逐句解释与逐页要求

对本次讲解范围内筛选后保留的实质性内容逐页逐句处理；纯目录、纯导读、纯过渡和仅含主题标题的非知识性页面依照筛选规则省略。每条有实质内容的句子、列表项、概念、符号、公式、代码和图表信息，都必须有可定位的解释或明确处理记录，不以整页摘要、段落大意或仅作翻译替代解释。

逐句解释采用连续、连贯的完整自然段，不使用项目符号或数字列表把每个句子的解释拆成零散条目，也不机械套用“是什么／为什么／怎么做”的分点模板。相邻且紧密关联的句子可以连贯成段解释，但仍应保持逐句对应和完整覆盖，不能省略其中的条件、逻辑转折或不同含义。通过自然的段落衔接和有实质含义的小标题深入讲清“是什么”“为什么”“怎么做”，对不适用的问题不强行填满模板。

完整覆盖不等于所有内容采用相同篇幅。简单内容应准确讲清，困难内容应展开动机、先决知识、中间步骤和适用条件。判断解释是否充分，以在已声明的学生基础下是否补齐理解当前内容所需的逻辑环节为准，不以固定字数为准。

首次出现的新概念、名词或符号，即使原文只是一笔带过，也应提供理解当前内容所需的定义、背景和作用说明。“首次出现”以整份交付讲义为主要范围，不以某个子 agent 第一次读到为准。

必不可少的先修知识应先补足到能够继续理解当前讲解单元；这只是起点，不是知识深度的上限。能够解释知识来源、揭示更一般结构或建立重要联系的内容，应按“知识延拓与贯通”主动展开，不因它不是当前页面或考试的最低要求就省略。必要背景就地讲清，较深入的延伸用清楚的小标题标明其性质。已经完整讲过的概念，在本单元给出必要的定义或含义提醒，并提供准确回指，不重复复制整段背景，也不只写无法定位的“前面讲过”。

本节中的“本页”指原材料对应的逻辑幻灯片或讲解单元，不指排版后的单张纸页。每个知识性讲解单元都要判断：学生在这里会卡在哪里？关键符号、当前含义和必要前提应能就地查明；较长的先修内容可以通过准确回指获取，无须让每个单元都从零重建全部知识。

知识性页面应指出有依据的关键思想、易错点或应用条件。纯目录、纯导读、纯过渡和仅含主题标题的页面只作内部登记，不进入讲义，也不解释其作用。重复和参考文献页面仍需登记并说明其作用，但不强行制造新见解；属于前述非知识性页面的重复页同样省略。无法辨认或未能解释的内容应明确记录，不把它们当成已完成。

### 概念解释要求

对重要概念力求达到迷你教科书的解释深度，并按实际需要检查以下方面：

- **记号和符号。** 说明定义、类型、取值范围及当前语境中的含义；必要时补充单位、维度或张量形状。已经解释过的关键符号仍应有简要提醒。
- **先决知识。** 指出依赖的定义、定理或方法，以及它们在此处如何使用。调用已有定理时，说明当前对象为何满足所需条件。
- **动机与例子。** 说明概念为解决什么问题而引入，给出有助于辨认其含义的具体例子；必要时给反例或边界例子。
- **边界与条件。** 说明结论的适用范围、条件所起的作用，以及可确认的失效情形。尚未确认的边界问题应如实标明。
- **等价表述与联系。** 仅在确有帮助且能说明关系时给出其他表述，指出与已学概念的联系，不把仅仅相似的内容说成严格等价。
- **常见错误。** 有依据时提示常见误区；自拟的易错情形应以示例呈现，不无依据地称为广为人知的错误。

这些是解释检查项，不要求每个小概念都重复出现六个小标题。对抽象内容优先选用合适的具体例子；使用类比时，说明对应关系和不适用的部分，不假设存在唯一最直观的类比。

### 知识延拓与贯通

**有助于真正理解和贯通知识的延拓应主动、充分展开，不以“本页没有写”“考试不考”或“暂时能理解当前句子”为由压缩成一句带过。** 可以追溯概念为何被提出，解释特例与一般情形的关系，比较不同方法的适用条件，连接前后章节或相关学科，并讨论具有依据的推广、限制与反例。

延拓应围绕当前知识中的具体问题展开，让学生清楚它从哪里接入、为什么值得理解、揭示了什么联系，以及需要哪些额外前提。需要例子、推导或反例才能把联系讲透时，就完整给出，不只是罗列术语或泛泛声称“二者有关”。

理解当前论证所必需的补充直接融入正文；更深入的延伸可用“延伸：……”或“与……的联系”等有实质含义的小标题组织，并自然回到当前主题。不得用泛泛导读、阅读清单或知识名词堆砌代替延拓，也不要求每个简单句子都附带一个拓展栏目。

不对有价值的延拓设置固定字数或篇幅比例，但应保持与本次主题的明确联系，不沿每个新名词无限分叉。延拓不能挤掉原材料的逐句解释，也不能把自拟推导或推断写成原课件结论；继续遵守来源、证据、适用条件和不确定性规范。跨子任务的延拓由主 agent 协调首次讲解位置和回指，避免各块重复从头展开。

### 论断性质与证明边界

先判断内容属于定义、假设、定理、近似、经验观察、解释性主张还是启发式说明，再采用相应的讲解方式。

定义应说明约定与含义；假设应说明用途与限制；定理应准确区分条件和结论；近似应说明所作简化及可确认的适用范围；经验观察应说明观察条件与证据边界。不要将定义当成待证明事实，也不要将经验结果改写成已经严格证明的普遍规律。

类比、直觉和个别示例用于帮助理解，不能单独替代一般命题的证明。补充证明时，应标注为讲解师补充，并给出可检查的步骤与依据。不能完成的证明或材料缺失的关键步骤，应明确说明缺口，不能用“显然”掩盖。

非数理内容应围绕其主张、依据、语境和适用边界解释，不强行添加公式或形式证明。

### 来源、不确定性与疑似错误处理

明确区分课件原文、参考资料支持的补充，以及讲解师作出的推断、补充推导或自拟示例。通过段落措辞、局部标签和可定位引用让读者辨认来源性质，不必为每句话机械添加相同标签。

不得把推断写成课件已经明确表达的结论。原材料不足以确定解释时，说明缺失条件；存在多种合理解释时，分别说明适用前提。自拟示例中的数据不能冒充原材料数据，静态推演不能冒充运行结果。

优先核查本次提供的课件、教材与参考材料。需要外部资料且任务允许时，优先查阅适合该问题的教材、原始论文或官方文档，并在补充内容附近标明出处。涉及软件接口或版本差异时，核对本次材料所用版本，不用未说明的其他版本替代原文。

教材引用记录书名、版本及实际可定位的章节或页码；论文记录题名、作者和相关位置；在线文档记录标题、链接及适用版本。没有实际查阅或无法核实的来源，不写成已经核实的依据，不编造页码、引用或书目信息。

发现疑似笔误、条件遗漏、符号冲突或推导错误时，先准确指出原文及其位置，再说明疑点、核查依据和建议修正。不得静默修改原文后，假装课件本来如此。来源之间存在分歧时，核对上下文、版本与定义，仍不能判断的就保留分歧，不任意选一个作为定论。

准确与可追溯优先于表面上的完整。存在无法确认的内容时，完整说明问题和影响范围，而非补出一个没有根据的确定答案。

### slide 页型专用解释规则

以下检查项按页面实际内容适用；同一页包含多种内容时，组合使用。不存在或无法确认的要素应在影响理解时说明，不为了填满模板而编造。

#### 代码页

保留原代码，并逐行解释其作用和与相邻语句的关系。不能只概述整段功能。至少按实际情况说明：

- 本页代码的目标、入口函数或核心函数；只是代码片段时，说明可见范围及缺失上下文，不虚构入口。
- 参数、局部变量和返回值的含义、类型及必要约束；区分函数定义中的参数和调用时传入的具体值。
- 所调用函数来自何处、如何使用、关键输入输出是什么；自定义函数缺少实现时，不猜测其内部细节。
- 算法步骤与代码实现如何对应；仅在确有差异、补偿或修复时，解释原因和解决的问题。
- 条件允许时，用一个具体输入推演关键变量、中间状态和输出，说明容易误读的分支与边界情况。

区分静态推演和实际运行验证。实际运行时记录相关输入、环境及结果；未运行则明确标注为静态分析。不能为了运行而擅自修改原代码；必要的修正版另行列出并说明改动。

#### 性能表格页

解释行、列、表头、单位、评价指标和比较基准，说明指标变大或变小各代表什么。存在足够可辨认数据时，引用至少两个相关数值解释差异或趋势；需要计算比值或变化量时，展示计算口径，不补造数据。

说明材料给出的实验条件，例如输入规模、硬件、实现方式、重复次数或误差信息。缺少会影响判断的条件时，应指出缺失，不将其默认为已控制。

明确区分数值观察、有材料支持的原因和可能解释。回答该表在所列条件下支持什么结论、不能支持什么结论，不把局部比较直接写成普遍性能原则，也不把相关变化自动解释为因果关系。

#### 练习页

不能只写“这是练习”。默认给出已知量、要求量、必要条件、解题思路、计算过程或判断步骤、最终答案，以及适用的错误检查或易错提醒。

条件充分时给完整解答，并在适用时检查单位、边界和结果是否满足题目要求。存在多解时说明解的范围或差异；条件不足时列出缺失项，给出明确标注假设的条件化解答，或说明为何当前无法确定唯一答案，不擅自补题。

若用户本次明确要求只给提示或暂不展示答案，按该教学要求调整解答的展示范围，并在处理记录中说明，不宣称已经交付完整解答。

#### 图示／状态转移页

按实际图示解释对象、标注、坐标或图例的含义，以及箭头、颜色、连线和状态变化表示什么。图中未说明的视觉编码，不应当作确定规则解释。

对于状态转移，先说明初始状态、转移规则和适用假设，再判断哪些输出或状态是 possible（可能）或 impossible（不可能），并给出对应路径、约束或不变量作为依据。不得仅因图中没有画出某条路径，就断言该路径不可能。

关键箭头、标签或状态无法辨认时，标明具体位置与受影响的判断。根据原图补绘或重建的示意应注明用途，不伪装成原始图像。

## 输出要求与结构

默认交付一份清晰、易懂、深入、详细的 LaTeX 编译讲义。用户本次明确指定其他交付格式时，按其要求处理，同时保留相应的内容覆盖和来源规范。

### 正文起始与禁止内容

最终讲义直接进入第一个有实质内容的讲解单元，不生成目录、导读、阅读指南或章节预告，也不以“学习路线”“章节导航”“本章你将学到”等名称换一种形式保留相同的导读内容。内部全局浏览、任务规划和覆盖记录不转写成讲义开场材料。

保留必要的单元标题、来源页码和交叉引用，用于准确定位知识；它们不需要汇总成可见目录页。纯目录、纯导读、纯过渡和仅含主题标题的原页依照筛选规则省略，不插入占位页或省略说明页。不得为了让每张原页都有一张输出页而填充内容。

### 原页对应与版面要求

默认将全部解释合并为一份讲义。每个保留的知识性逻辑幻灯片对应一个可独立定位的讲解单元，不限定为一张输出纸页，也不默认生成一个独立文件。讲解单元可以跨越多页；单元开头展示对应原页或按筛选规则保留的可定位局部内容，后续页面保留来源编号和续页标识。按规则省略的非知识性页面不建立讲解单元。

保留的展开帧可以在同一单元内按过程展示，并标注各帧来源。原页或原图应清晰可读，不能为满足固定版式而过度缩小。必要时展示局部放大图，但保留与完整原页的对应关系。

对保留的英文材料，继续展示清晰可读的原始英文页面，并在逐句原句块中提供逐项对应的中文译文。逐句区以中文译句为主体，对应英文仅放在该译句后的一组括号中，不另起独立英文原句段落，也不重复排出“英文原句＋中文译句＋解释”的三段式内容。单元开头的英文原页展示不受这一逐句区规则限制。术语译法保持一致，公式和代码标识符不得因翻译被擅自改变。翻译与解释应可区分，不能把扩展解释混进原文译文。

每个讲解单元应让读者找到来源位置、对应原文、必要背景、逐句解释，以及适用的推导、例子和易错点。具体小标题随内容安排，不必为不存在的内容制造空白模板。末尾可以补充单元要点或自检，但不能替代前面的解释。

### 逐句原句与连贯解释的排版

**原句与解释必须有可见的版面区分。** 每条原句或紧密关联的原句组使用统一的浅色底块，默认浅灰底色 `#F3F4F6`，保留适当内边距和段前段后间距。解释位于其后，采用无底色的连贯自然段。浅色底应落实到最终生成的 PDF，而不是只在 Markdown 中加引用符号或写“这里使用浅色底”。

中文材料的原句块保留对应中文原句。英文材料的原句块固定采用 `中文译句。（原文：English sentence.）` 的顺序：中文在前，括号中放对应的实际英文原句，不能只写“第几句的翻译”，不能把英文大意冒充原文，也不能在括号外重复该英文句子。中文译句是阅读主体；括注可使用较弱的字重或略小字号，但必须清晰可读，完整保留原意、条件、公式和代码标识符。来源位置用稳定的单元或句子标识关联，不与解释文字混在译句中。

解释正文用完整自然段展开，不把每句解释做成项目符号、编号列表或逐项问答卡片。需要呈现公式推导、代码、表格，或标记证明步骤与代码行号时，保留适合这些内容的必要结构，并用连续文字讲清它们的关系；不得借步骤编号重新把整段解释拆成碎片化清单。原材料本身的列表形式可以在原句区保留，不意味着解释区也必须照抄列表。

原句块应允许自然换行；内容较长时采用可分页的排版方式，不裁切、不遮挡，也不为了保持单个色块而大幅缩小字号或留下整页空白。不要把短原句、标题和解释强制分别放到独立纸页。多个子 agent 必须使用主 agent 提供的同一原句样式与正文模板。

### 标题、统领句与视觉层级

**解释不能从头到尾只用相同字号、相同字重的连续文本；也不能只靠颜色表达层级。** 主 agent 应统一标题、子标题、关键统领语句和正文的样式，用字号、字重、间距与局部浅底色共同呈现逻辑结构，不要求为每个层级更换字体家族。

| 内容角色 | 默认呈现要求 |
| --- | --- |
| 知识性单元标题 | 最大一档标题字号、加粗，配统一浅蓝底色，默认 `#E4EDF7`。标题直接服务后续内容，不单独扩写为导读或占满一页。 |
| 解释内部的小标题 | 比单元标题低一档、比正文醒目，使用较轻的浅蓝底色，默认 `#F0F5FA`；名称应体现实际子问题或逻辑环节。 |
| 关键统领词、短语或短句 | 只对真正统领后文的部分局部加粗或加浅米色底，默认 `#FFF3DD`；同一层级采用统一方式。 |
| 普通解释正文 | 保持稳定、清晰的正文字号与正常字重，无整段底色；通过自然段、必要留白及明确衔接展开。 |

上述颜色可按实际版式微调，但应始终保持浅色背景与清晰深色文字，并统一各类元素的视觉含义。不要使用大片高饱和底色，不把所有句子都加粗或高亮，也不对整段长解释铺底色。即使不依赖颜色，读者也应能从字号、字重和位置辨认层级。

小标题和统领语句应体现真实逻辑，例如概念动机、关键前提、推导转折、结论边界或知识联系，不强制每句都套相同栏目。用于引出后文的完整关键句可作简洁的浅底提示；普通长段落仍保留为正文。主 agent 合并时应统一各子任务的样式，保留已经充分的解释内容，不为追求视觉简短而删去推导与细节。

### 数学表达与 LaTeX 规范

以下规则针对最终 `.tex` 源文件。若先写 Markdown 中间稿，应检查转换后的 LaTeX，不把中间稿的数学分隔方式直接当成最终源文件规范。

定义和定理的自然语言部分保留为正文或相应的定义、定理环境，只有其中的数学表达进入数学模式。不得为了充分使用 LaTeX 而把本来清晰的自然语言全部符号化。

- 行内数学内容使用 `$...$`，例如变量、简短表达式和集合记法。
- 无编号独立公式使用 `\[...\]`，需要编号的公式使用 `equation`。
- 多行对齐推导根据编号需要使用 `align` 或 `align*`；不要再在其外部套独立公式分隔符。
- 短小且需要作为一个整体的公式组，可以在数学环境内使用 `aligned`。长推导应按逻辑步骤拆分并保留文字解释；需要跨页时采用适合分页的结构，按需设置 `\displaybreak` 或 `\allowdisplaybreaks`。这两个命令不能使 `aligned` 内部跨页。
- 数学模式中的说明文字使用 `\text{}`。公式中的变量与说明文字应明确区分，必要的中文须经过实际编译检查。
- 正确加载所用环境依赖的宏包，统一符号、公式编号和交叉引用；需要回指的关键公式应有稳定标签。
- 在提升精确性或可读性时使用数学符号，例如 `$\forall x \in S$`，但不以符号数量衡量解释深度。

公式环境与分页行为的实现参考为 AMS 与 LaTeX Project 的 *User’s Guide for the amsmath Package*，第 3、6 节。[^amsmath]

### 交付文件与编译要求

默认交付讲义 PDF，并附可继续修改的 `.tex` 源文件、编译所必需且可交付的资源，以及简短编译说明。用户明确只需要某种产物时，按本次约定交付。字体注明依赖，不打包分发字体文件。

根据实际环境选择可用的编译引擎、中文支持和宏包，先验证基本编译链路。正式编译后检查日志和生成页面，修复实际影响内容或阅读的问题。必要资源路径应清楚，源文件不应依赖未说明的临时位置。

环境无法编译时，可以交付已完成的源文件和缺失依赖说明，但必须注明未编译，不能声称 PDF 已成功生成。文件存在不代表已经通过内容与版面验收。

## 输出的语言风格

### 术语与中文表达

解释正文输出语言默认为中文。解释正文中的专业术语保留英文原词，在整份讲义首次出现时采用 `English term（中文释义）`，例如 `attention（注意力）`、`fine-tuning（微调）`、`ablation（消融）`、`retrieval（检索）`、`policy gradient（策略梯度）`、`representation（表示）`、`benchmark（基准）`。这些仅为格式示例，具体释义应服从本次课程语境，不机械翻译。

后续同一含义保持一致，当前单元确有需要时可补简短提醒。同一个英文词在不同语境中含义变化时，重新说明该处含义。保留原文引用、代码标识符及数学符号，不能为统一译法而改变原始内容。

逐句原句块中的中文译句不套用正文的“英文术语在前”格式；它以中文表达为主，对应英文原句只放在译句后的括号中。必须保持原样的数学记号、代码标识符以及没有可靠译法的专名除外，但不能借此把整条译句重新写成英文。

需要自称或标明补充内容的提供者时，统一使用“讲解师”，例如“讲解师补充”。不在普通解释中无必要地反复自称。

### 写作方式

写作风格参考 Andrej Karpathy 和 Kaiming He，以浅显易懂、深入浅出为目标，并以具体要求落实：从当前问题出发；必要时用一个贯穿的小例子；每个关键步骤交代理由；先建立清晰对象与关系，再引入必要术语；不以口号或形容词代替机制解释。

减少模板化的铺垫、生硬转折以及不必要的破折号和双引号。句式与标点偏好只约束新写的解释文字，不影响原文引用、代码字符串、数学符号或确有必要的概念对比。语言流畅不能以牺牲准确性、条件说明或推导细节为代价。

## 质量验收与异常处理

### 内容覆盖与正确性验收

交付前按原材料逐单元检查，不能只凭输出篇幅判断完成度。

| 验收维度 | 通过条件 |
| --- | --- |
| 内容覆盖 | 本次范围内每个保留的知识性讲解单元均有对应内容；实质性句子、公式、代码和图表信息没有无说明遗漏。已解释、重复回指、合并展示、非知识性已省略与待确认内容能够区分；省略判定只在内部登记，不要求在讲义中逐页说明。 |
| 解释充分性 | 在已声明的学生基础下，关键符号、前提、步骤依据与适用范围清楚；没有只换一种说法或只列结论而遗漏必要解释。 |
| 论证与结果 | 定义、假设、定理、近似、经验结果和推断没有混淆；关键计算与推导经过可行的核查；静态推演与实际运行明确区分。 |
| 来源与不确定性 | 原文、外部补充、自拟示例和推断可辨认；引用可定位；疑似错误、条件不足与未解决问题已标明。 |
| 跨块一致性 | 术语、符号、编号、回指和视觉样式一致；首次讲解位置明确；跨页证明、代码示例及后续结论没有断开。 |
| 知识延拓 | 有助于理解来源、推广、边界和重要联系的内容没有仅因不在考试范围而被压缩；延拓有明确主题关联、必要依据与来源区分，没有替代原材料解释或无关发散。 |
| 任务粒度 | 子任务按章节内小主题和完整论证单元组织，依照默认粒度结合难度分配，不默认整章打包，也不按每句话机械拆分；超出参考范围的理由可查。 |
| 称谓 | 需要自称或标注补充内容时统一使用“讲解师”，普通说明不机械重复自称。 |

### 编译与版面验收

对最终生成文件检查保留原页的对应、翻译对应、单元定位、公式编号和交叉引用。确认没有生成目录、导读、阅读指南、章节预告，以及纯过渡或纯标题页面的独立解释、占位页和省略说明页。

逐句区应实际显示浅色底原句块，英文材料应采用中文译句在前、对应英文仅在括号中的格式；解释正文应是连贯自然段，不是分点清单。标题、小标题和关键统领语句应体现统一的字号、字重与局部浅底层级，不能合并后全部退化为相同正文样式，也不能整页过度高亮。

查看渲染后的页面，检查是否存在截断、遮挡、乱码、缺图、代码溢出、公式跨页不当或不可读缩放；额外检查原句色块的换行与分页，避免短标题或短原句占满一页。

覆盖检查不能被抽样阅读代替。长文件可以借助自动检查辅助发现问题，但仍须核对全部原页对应关系；复杂公式、图表、代码和出现异常的页面必须查看实际版面。记录实际完成的检查范围，不把未检查部分描述为已验收。

### 信息缺失、工具失败与部分交付

工具、材料质量或运行限制导致工作无法完成时，说明受影响范围、已经完成的部分、待处理事项，以及继续完成所需的条件。无法辨认的原文、未完成的证明或待确认的结论不能算作已经解释完毕。

在不改变任务目标的前提下，可以继续处理不受影响的内容，并标出对未解决问题的依赖。不能为了赶进度将未完成部分缩成摘要后声称已完整交付；可以分批交付，但每批都应有明确范围和状态。

未实际编译，不得声称编译成功；未运行代码，不得声称运行验证通过；未读到原文，不得声称已经逐句覆盖。最终说明应与实际产物和检查记录一致。
